## EVIDENCE

### Schema

The actual SQLite schema was executed with the bundled FTS5 trigram tokenizer
and inspected with `sqlite3 :memory: ".schema"`. Implemented tables:

`schema_version`, `meta`, `groups`, `clips`, `clip_formats`, `copy_buffers`,
`settings`, `migration_state`, and `clips_fts`.

Key properties:

- `PRAGMA user_version` is authoritative; v1 up and down migrations pass.
- WAL, `busy_timeout=5000`, `synchronous=NORMAL`, `foreign_keys=ON`,
  `temp_store=MEMORY`, and incremental auto-vacuum are configured.
- `clips.dont_auto_delete` remains independent from `is_pinned`.
- `copy_buffers` is normalized with slots 1..5.
- FTS5 `trigram` indexes `preview_text`, `quick_paste_text`,
  `text_content`, and `description`; external-content triggers cover
  insert/update/delete.
- Image formats always use `data_path`; inline format data is capped at
  64 KiB. Thumbnails are stored separately under `thumbs/`.

### Storage API

Implemented:

- `Storage::open`, `open_data_root`, WAL/read-pool access, migrate/checkpoint/
  optimize/database-size operations.
- `insert_clip` with SHA-256 content/format hashes, dedupe, multi-format
  transaction, blob split, and `InsertOutcome`.
- `insert_many` for synthetic/migration-style batch insertion.
- `search_clips` with FTS5 trigram, short-query LIKE fallback, group filter,
  keyset cursor, bounded limit, sort modes, and deferred/estimated total.
- `get_summary`, `get_clip`, soft/restore/clear/purge delete paths, retention,
  and orphan blob GC.
- Group create/rename/delete/move/tree listing and clip move.
- Pin/unpin with stable pin order; sort-order updates.
- Copy-buffer read/assign/rename/clear with 1..5 validation and persistence.
- Settings JSON get/set, centralized defaults, revisions, and legacy key
  conversion helpers for T6.
- Content-addressed blob and thumbnail helpers; DB stores relative paths and
  SHA-256, never the image blob.

### Clipboard API

Implemented:

- `ClipboardSource` trait with a `WindowsClipboardSource` implementation and a
  synthetic memory source used by tests.
- `AddClipboardFormatListener` hidden message-only window, 150 ms debounce,
  `OpenClipboard` retry (5 attempts/10 ms), and per-format failure isolation.
- Capture of `CF_UNICODETEXT`, `CF_TEXT`, `CF_OEMTEXT`, `HTML Format`,
  `Rich Text Format`, `CF_DIB`, `CF_DIBV5`, `PNG`, `CF_HDROP`, and custom
  HGLOBAL-backed formats.
- Foreground process name/window title capture; failures become `None`.
- DIB/DIBV5 decoding to PNG while preserving raw DIB bytes, plus 256 px
  thumbnails.
- Content/format SHA-256 generation, multi-format merge, warnings, size limits,
  ignore list, and self-write content-hash suppression.
- Explicit `Paste` IPC returns `DITTO_E_NOT_IMPLEMENTED`; T4 owns paste.

### IPC messages

Extending DTP1 with additive/defaulted JSON fields:

- `GetClips { query, group_id, limit, cursor, sort }`
- `Search { query, group_id, mode, sort, limit, cursor }`
- `GetClip { clip_id }`
- `Paste`, `SetPinned`, `MoveToGroup`, `Delete`
- `GetGroups`, `CreateGroup`, `RenameGroup`, `DeleteGroup`, `MoveGroup`
- `GetCopyBuffers`, `CopyBufferAssign`, `CopyBufferClear`
- `GetSettings`, `SetSettings`
- Responses: `Clips` (including `total_is_estimate`), `Clip`, `Groups`,
  `CopyBuffers`, `Settings`, `Ok`, `Error`
- Events: `ClipAdded`, `ClipUpdated`, `ClipDeleted`, `GroupChanged`,
  `SettingsChanged`, `ClipboardState`

`Hello`, `ShowPopup`, `HidePopup`, and DTP1 framing/ACL behavior are unchanged.
`PipeServer::start_with_handler` adds a narrow request callback; the default
`PipeServer::start` keeps the previous behavior when no handler is installed.

### Core service wiring

`core_service.rs` starts storage and clipboard monitoring, handles the listed
IPC requests, broadcasts clip/settings/group events, maps storage errors to
stable DTP1 error codes, and returns `NotImplemented` for paste.

`apps/ditto/src-tauri/src/lib.rs` changes are limited to:

- adding the `core_service` module;
- constructing storage/core service in setup and retaining the pipe handle;
- stopping the core service on tray exit.

Tray menu behavior, global hotkey handling, Tauri configuration, settings
window behavior, and popup visibility logic were not changed.

## RISKS

- FTS search with `Recent`/`Oldest` uses FTS rowid traversal to avoid sorting
  the full match set; pinned/group-order search still uses SQL ordering and may
  need a larger real-world corpus profile. Browse/list queries retain the
  documented `sort_order` behavior.
- Deferred `total_is_estimate` means clients must render a lower-bound count
  such as `200+` when `next_cursor` is present; T3/T5 must honor the flag.
- The hidden clipboard listener is Windows-only and currently has no automated
  live listener test, so listener registration failure is reported as startup
  failure rather than self-healed in tests.
- The app now exits setup if storage migration or clipboard listener startup
  fails; this is intentional fail-closed behavior but needs integration QA.
- No git commit exists; the coordinator must inspect and commit the listed
  files. Generated build inputs may need to be excluded or regenerated by CI.
